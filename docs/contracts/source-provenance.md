# Research source provenance

Open a Research card from Space. Use **Links** to connect an approved source to its `sources` input. Select **Capture source** to save a project-owned version. The current formats are a managed TXT, Markdown or PDF file, a PNG, JPEG or WebP image, a PCM WAV recording, an inline text source, or a Site reference with a saved quote. Select the individual image when the link comes from a Gallery. **Add manual source** saves text entered in Research. Search matches source titles and text across all saved versions. The count below **Search saved sources** shows how many versions are indexed and updates as new versions are saved.

The record stores a source UUID. A linked source also records the Data Link UUID, source node UUID and the chosen asset UUID for a Gallery item. The upstream SHA-256 identifies the exact plain text, Site reference or managed asset reference. A saved source revision covers its title, captured material and upstream revision. Core validates both digests and resolves the asset and version IDs against the project's managed storage. Capturing a Site reference uses only the saved address, title and quote from the same project. Text is rendered literally.

Each citation stores the source UUID, the saved revision, and an inclusive start and exclusive end as UTF-8 byte offsets. Core rejects invalid boundaries, blank selections and excerpts beyond 8 KiB. A conclusion records the selected citation IDs and a digest of the active saved versions for the whole card. **Source changed** means the linked resource has a different current revision. **Link unavailable** means the live resource or permission could not be resolved. A conclusion based on an older context remains visible with its status and citations. **Capture latest version** records a new version through the same live link and keeps the earlier material available under **Saved source version**. A revoked link disables that action. The project retains the saved copy for local reading.

A Research card allows up to 64 sources, 16 versions per source, 256 citations and 128 conclusions. Each saved text body can contain up to 64 KiB and each conclusion up to 16 KiB. The aggregate serialized card payload is limited to 1 MiB. Core rejects out-of-bounds changes before publishing a project revision.

## Local PDF text extraction

Connect the `files` port from a managed PDF card. **Capture source** reads the text layer in page order and saves it with the verified attachment and method `textLayerV1`. The parser combines the nonempty page text with newlines. Citations use UTF-8 offsets in the saved extraction. A PDF with no extractable text returns `NO_EXTRACTABLE_TEXT`. Malformed and encrypted documents return `PDF_UNREADABLE`. **Enter PDF text** saves a literal excerpt with method `manual`. Core checks that the file's version still matches the one selected when text entry began. If the source changes later, **Enter updated PDF text** saves the next version and preserves previous citations.

Automatic extraction accepts up to an 8 MiB input, 256 pages, 8 MiB per load-time stream or decoded page and 64 KiB of text. Core verifies the asset size and SHA-256 before sending bytes over a private pipe to a separate invocation of the installed Core executable. The worker receives no project path or inherited environment. Its parser works locally, with an 8-second deadline and a 256 MiB process memory limit on Windows. A quota, timeout or worker failure prevents publication of a partial version. PDF actions and embedded scripts have no execution path in text extraction. [Lopdf documentation](https://docs.rs/lopdf/latest/lopdf/)

## Local audio and transcripts

Link a PCM WAV file's `files` port and choose **Capture source**. Core checks the asset size and SHA-256 and measures the duration of the verified bytes. Select the saved recording to play it. **Add transcript** or **Edit transcript** saves a new version with ordered, non-overlapping start and end times in milliseconds, up to the duration of the recording. A transcript can contain 1,024 segments and 64 KiB of text including separator newlines. A segment displays a time range button to seek to its start. [WAVE format fields](https://learn.microsoft.com/windows/win32/api/mmeapi/ns-mmeapi-waveformatex)

Citations use UTF-8 byte offsets in the saved text joined with newlines. Audio citations show the start and end of the segments touched by those offsets. Changing a transcript marks earlier conclusions stale and leaves their precise citations readable. After removing a Data Link, Research retains access to the local snapshot. Playback uses a verified temporary copy and an opaque media URL scoped to the trusted desktop frame. Core checks the current project ID and the saved source and revision. The URL expires when the player closes, the project changes or one hour passes. Local audio and manual transcripts work from a restored ZIP.

### Automatic transcription

Start a separately installed whisper.cpp server with a model that supports the recording's language. For example, run `whisper-server --host 127.0.0.1 --port 8080 --model path/to/model.bin`. Forge sends audio directly to `http://127.0.0.1:8080/inference` and does not follow redirects. The provider and its model are managed outside Forge. [whisper.cpp server](https://github.com/ggml-org/whisper.cpp/tree/b5907/examples/server)

Select the current saved version of an audio source with an active Data Link. Choose **Transcribe automatically**, select a language and choose **Review recording**. Compare the file size, WAV SHA-256 and saved revision, then select **Allow sending this WAV** and start transcription. The approval is single-use and expires after five minutes. Start a new review if the source, link or language changes. Core verifies the current link, its sharing permission, and the recording identity before export and again before transmission. The 16 MiB limit applies to the full WAV. The provider receives the WAV as `recording.wav` and transcription options. Requests time out after three minutes and can be canceled.

Review the returned segments and choose **Save automatic transcript** to create a new version. Forge rechecks the current revision and link permission before saving. The new version records the provider, input revision, requested and detected languages, UTC generation time and response SHA-256. Earlier versions and their citations remain available. The project ZIP includes the saved transcript and provenance.

## Backup and verification

Project backups include the card payload, revision history, and the original managed asset versions referenced by Research. Restoring a ZIP as a copy preserves the saved source IDs, revisions, offsets and conclusions under the new project identity. The browser profile for any linked Site follows the normal restore rules. [Recovery runbook](../runbooks/recovery.md)

Run `node tests/research-desktop.mjs` after building the Windows Core and desktop UI. The synthetic fixture covers a multiline Unicode citation, managed image preview, a saved Site quote, manual source search, stale conclusions, a removed link and ZIP restore into a clean desktop profile. PDF cases cover text across two pages, citation offsets, a graphics-only page, malformed input, page quota, rejection of the wrong attachment version and restored offline text.

Audio cases include a verified PCM WAV, rejected malformed input, seeking with time ranges, invalid and overlapping timestamps, citation provenance after transcript edits and playback after restore.

Run `node tests/research-transcription-desktop.mjs` to verify approval and cancellation, the exact WAV payload, response validation, a revoked source and clean-profile restore. The default test uses a loopback fixture. The optional `--real` case uses `FORGE_TRANSCRIPTION_REAL_PORT` and `FORGE_TRANSCRIPTION_REAL_WAV` to run against whisper.cpp with the qualification recording.
