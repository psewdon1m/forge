# Intelligent context and provider requests

In Space, add **Intelligent** and use **Links** to connect the supported outputs. Select specific sources and enter a request. The source menu shows each card's `@name` and stable ID suffix, including when two cards share a name. Select individual captured Research materials or choose a Dataset row range of up to 100 rows. Palette contributes its current aggregate swatches. Site contributes the quote already saved to the project. A text link contributes the literal text. Binary files, browser sessions, credentials, file paths and unknown Plain payloads stay outside the model request.

**Review context** shows the exact provider, model, byte count, material text, revisions, content digests and available citation offsets. It prepares an approval bound to the selected link IDs, node IDs, resource IDs, revisions and exact request bytes. Renaming a card preserves its identity. The review expires in five minutes and has one send attempt. Site material requires **Allow the Site quotes in this review**, including when a Research snapshot contains the quote. Approving one review grants no permission for the next.

Core resolves the selections again immediately before handing them to the provider. It rejects a detached link, a changed current Palette or Research source, and a Research source marked **Keep in this project**. Credential-shaped text and named credential columns are blocked. This check covers recognizable formats and users can mark any Research material private. Core caps the underlying source budget at 16 MiB and accepts up to ten materials. The complete prepared message has a conservative UTF-8 byte budget of at most 16,000, including prompt and envelope. An Ollama request reserves room for the selected output and model template within the model's reported context. If a selection exceeds a limit, narrow the material and review again.

## Providers

**Local deterministic test** produces a stable textual response from the selected manifest. It needs no connection. **Ollama on this computer** connects directly to `http://127.0.0.1:11434`. Enter an installed model name and choose an output size of 256, 512, 1,024 or 2,048 tokens. A review uses `/api/show` to confirm the local model's capabilities and context size. It sends only the model name during that check. **Send** rechecks the installed model before using `/api/chat`. The adapter rejects advertised remote models and redirects. The Forge build does not install a model. [Ollama model metadata](https://docs.ollama.com/api/show) · [Ollama chat API](https://docs.ollama.com/api/chat)

The adapter supplies a system instruction and one user message containing the request and literal materials. It offers no tools or command execution. It accepts completed assistant text and displays it literally. **Cancel request** stops the local operation and closes a pending provider request. When data may already have reached Ollama, the UI says processing may continue there. Before a send failure or cancellation, any earlier completed result stays visible.

## Result storage and verification

An answer lives in memory until **Save result to project** commits it. The saved record includes UTC time, provider and model IDs, request and response digests, literal response text, and the manifest with extraction versions and usable citation offsets. The manifest remains readable if the old materials can no longer be resolved. The full prompt and outgoing material bodies are excluded from the result record. Diagnostics do not record prompts, materials or answer text. The project ZIP carries saved records. The application limits each Intelligent card to twelve saved results and each saved answer to 16 KiB of UTF-8 text.

Run `node tests/intelligent-desktop.mjs` after building the desktop and Windows Core. It exercises the deterministic provider and an isolated HTTP fixture for the Ollama adapter, including Gallery → Palette, selected Research and Dataset materials, separate Site approval, identity after rename, prohibited and revoked sources, quota, cancellation, refusal and ZIP restore. The fixture override is available only in an unpackaged qualification launch.
