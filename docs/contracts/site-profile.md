# Site Plain v1

Choose **Add Site** in Space, open the card, enter an HTTPS address and select **Go**. **Back**, **Forward** and **Reload** act on the browser in the open card. The address bar belongs to Forge. Navigating within a page updates the bar. Connection errors and HTTP 401/403 have explicit status text. Pages that return an ordinary success response while asking the user to sign in are displayed as sent by the site.

**Capture current page** opens a preview with the current page title and HTTPS URL. Review this address and enter a manual quote of up to 16 KiB of UTF-8. **Save reference** commits the title, sanitized URL and quote as one project revision. **Discard reference draft** closes the preview. Clear or save a draft before leaving the Plain.

The versioned payload is `forge.site` with `schemaVersion: 1` and `{"reference":null}` or `{"reference":{"url":"https://example.test/reference","title":"Reference","quote":"User-entered text"}}`. Both desktop and Core validate the address. Only HTTPS is accepted, and a reference excludes embedded credentials, query and fragment. The reference retains its path. Browser storage and downloads live outside the project snapshot. A backup includes explicitly saved references. The archive contains neither Site sessions nor browser cache. Space displays the card label, saved page title, origin and reference status using app chrome. A page mounts when the Plain opens a saved address or the user navigates from inside the Plain.

## Browser and profiles

Site is a sandboxed Electron `WebContentsView` alongside the trusted local renderer. Its web preferences enable context isolation and web security, disable Node integration and webview tags, and omit the application preload. Site denies permissions, device access and screen capture. Main frame and subframe navigations and redirects accept HTTPS without credentials. Blank subframes are supported. The native browser view stays within the rectangle allocated by the trusted renderer. Closing the Plain detaches the view and closes any pending browser or login window. Forge Core and application commands require the trusted local main frame. [Electron security](https://www.electronjs.org/docs/latest/tutorial/security).

Chromium persists a distinct session partition for each project ID and Site Plain ID under Forge's application data. Reopening the same card reuses its profile. Copying a card changes the Plain ID. Restoring a project as a copy changes the project ID. Both operations open independent profiles. **Clear site data** asks for confirmation, closes the active view and the sign-in window, terminates connections, clears Chromium data and clears the HTTP authentication cache for that profile. A new navigation is explicit. Server-side account sessions are managed by the website. [Electron Session API](https://www.electronjs.org/docs/latest/api/session#sescleardataoptions).

## Sign-in windows and downloads

A page request to open a window is intercepted. Forge shows the requested origin and offers **Open sign-in window** or **Dismiss window request**. The approved window uses the same Site profile, stays sandboxed, disables nested windows and displays its current HTTPS origin in the native title. Closing it prompts the user to reload and verify the session. The supported flow shares browser session data. Some identity providers require the opener connection or forbid embedded browsers. Qualification on a deployment's actual identity provider is separate.

For a Site download, Forge checks the initiator against the active page origin and verifies that the redirect chain uses HTTPS. The current profile admits one pending item. A file needs an announced size between 1 byte and 32 MiB. Forge pauses it in private staging and shows the filename and size. **Save download** opens a native Save dialog. Forge checks the completed size, marks the file as Internet content on Windows, and publishes it at the chosen location without replacing an existing entry. Forge never launches the file. The destination filesystem must support hard links and the Windows Internet zone stream. Canceling the picker or leaving the Site cancels the pending item. Unapproved offers expire after two minutes. Approved downloads time out after ten minutes. [Electron DownloadItem API](https://www.electronjs.org/docs/latest/api/download-item).

## Qualification

Run `node tests/site-desktop.mjs` after building the UI and Core. It exercises the product controls on a Windows desktop against a synthetic loopback TLS server, including profile restart, logout isolation, approved popup, approved downloads, failure states and references. The fixture certificate override exists only in an unpackaged qualification run and verifies the exact certificate fingerprint for loopback.

Run `node tests/shooting-project-windows.mjs` to generate a project and a verified ZIP under `.local/qualification/shooting-project-*/`. The ZIP opens through **Settings → Backup**. The fixture includes synthetic lighting plates, Checklist, Scheme, Dataset, a Site reference, a call sheet and the versioned Gallery, Palette and Metadata scenario. It checks that cancellation leaves the last successful result available and that restored analyses still reference the exact input versions.
